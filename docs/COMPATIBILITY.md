## 2. 运行时兼容

| 项 | 规则 |
|---|---|
| Python | 锁定 `3.12.x`（**已决策**，见 `TECH-BASELINE.md` §2.1）。跨 minor 升级（3.12 → 3.13/3.14）**必须团队确认**，并重跑全部测试。注意：开发机系统默认是 3.14，**项目环境必须显式使用 3.12** |

> ✅ **已决策（2026-09-16）：Python 锁定 3.12.x。** 开发机系统默认 3.14.4 与之并存，
> 项目一律通过 `.venv` 使用 3.12。详见 `TECH-BASELINE.md` §2.1。

## 3. 数据库 Schema 兼容

| 变更类型 | 兼容性 | 处理方式 |
|---|---|---|
| 新增可空列 / 新增表 | 兼容 | 迁移脚本，不需停机 |
| 新增非空列（有默认值） | 兼容 | 迁移脚本 |
| 新增非空列（无默认值） | **破坏** | 需三步走：加可空 → 回填 → 收紧 |
| 改列类型 | **破坏** | 团队确认 + 迁移 + 备份 |
| 删列 / 改名 | **破坏** | 团队确认 + 版本化 |
| 改资源 ID 语义 | **严重破坏** | 需要数据重写与三方同步，**禁止轻易进行** |

**纪律**：Alembic 迁移必须与代码同一提交；**禁止手工改库而不留迁移**。

## 4. 接口兼容

| 变更 | 分类 | 要求 |
|---|---|---|
| 响应新增可选字段 | NON-BREAKING | 更新 `API_CONTRACT.md`，通知 C |
| 请求新增**可选**字段 | NON-BREAKING | 更新契约，A 可不实现 |
| 请求新增**必填**字段 | **BREAKING** | 升版本或团队确认 + 通知 A |
| 字段改名 / 删除 / 改类型 | **BREAKING** | 升版本 |
| 收紧校验（原本接受的值现在拒绝） | **BREAKING** | 容易被忽略，必须显式标注 |
| 新增枚举取值 | 视消费方而定 | 若 C 用 `switch` 穷举则属 BREAKING，需通知 |
| 错误码变化 | **BREAKING** | C 依赖错误码分支 |

**流程**：改契约文档 → 标 `BREAKING`/`NON-BREAKING` → 通知 A/C → 更新测试与示例 → 才动代码。
