## 1. 为什么需要这份文档

赛题把"敏感信息保护"列为**实现约束**（即合规要求，非加分项）。而本平台的采集面天然会接触到敏感数据：

| 数据来源 | 可能携带的敏感信息 |
|---|---|
| 容器环境变量 | API Key、数据库密码、Token、第三方凭据 |
| 进程命令行（`cmdline`） | `--password=...`、`--token=...`、内网地址 |
| 业务日志 | 用户身份、手机号、身份证、会话 ID、请求体 |
| Agent 任务轨迹 | 工具调用参数、用户输入、外部服务凭据 |
| 配置 / 部署 | ZSvirt 凭据、数据库连接串、局域网地址 |
| 事件原始载荷 `Event.raw` | 上述全部（因为它是原样保存的） |

**B 侧的定位**：B 是数据的**汇聚点**，也是最容易把敏感信息扩散到 API 与前端的一环。因此脱敏的第一道有效关口在 B 的 `normalize` 模块（A 的探针侧做不做脱敏是 A 的决定，但 B **不得假设 A 已经脱敏**）。

---

## 2. 三层防护

```
A 探针（可选前置脱敏）
      │  上报
      ▼
B: ingest  ──▶  normalize（★ 主要关口：字段过滤 + 脱敏）──▶ events / graph
                                                              │
                                                              ▼
                                             B: api ──▶ C 前端（不返回敏感字段）
```

| 层 | 责任方 | 措施 |
|---|---|---|
| 采集层 | 成员 A | 可选：探针侧不采集明显敏感字段（如跳过环境变量） |
| **汇聚层** | **成员 B** | **强制**：字段过滤 + 脱敏管道；`Event.raw` 入库前必过 |
| 展示层 | 成员 C | 不渲染敏感字段；不在前端日志打印完整响应体 |

## 3. 字段过滤规则（丢弃而非脱敏）

以下内容**直接丢弃，不入库**：

| 目标 | 匹配方式 |
|---|---|
| 环境变量类字段 | 键名匹配 `*_KEY`、`*_TOKEN`、`*_SECRET`、`*_PASSWORD`、`*_PASSWD`、`*_CREDENTIAL`、`AWS_*`、`OPENAI_*` |
| 凭据 / 证书 | 键名匹配 `authorization`、`cookie`、`set-cookie`、`private_key`、`certificate` |
| 连接串 | 值匹配 `://[^:]+:[^@]+@`（含用户名密码的 URL） |
| 已知的密钥形态 | 值匹配长随机串启发式规则（如 `sk-`、`ghp_`、`AKIA` 前缀） |

> **默认策略**：**白名单优先**。`attributes` 只接受契约中显式声明的字段，未声明字段默认丢弃，而不是默认保留。

## 4. 脱敏规则（保留但掩码）

对确实有诊断价值、但可能含敏感信息的字段，保留字段本身、掩码其内容：

| 字段 | 处理 | 示例 |
|---|---|---|
| `process.cmdline` | 参数值掩码，保留参数名与命令 | `python serve.py --api-key=*** --port 8000` |
| `Event.message` | 命中规则时掩码匹配片段 | `connect failed to db://user:***@10.x.x.x:5432` |
| `Event.raw` | **整体走脱敏管道**；无法安全脱敏的键直接删除 | — |
| IP 地址 | 【待确认】是否掩码内网地址；建议**保留**（拓扑关联需要） | — |
| `labels` / `annotations` | 按 §3 规则过滤键名 | — |
| 身份标识（用户 ID / 手机号） | 哈希化（单向），保留可关联性、去除可读性 | `user_7f3a9c` |

**掩码实现要点**：
1. 脱敏必须**幂等**（重复执行结果一致）。
2. 脱敏必须**可审计**：记录"某字段被脱敏"的标记，但不记录原文。
3. 脱敏后的事件仍须满足 `DATA_MODEL.md` 的字段契约（不得因脱敏导致必填字段缺失）。

## 5. 访问控制说明（赛题要求"访问控制说明"）

| 项 | 结论 |
|---|---|
| 认证 | 首版**默认关闭**；可选**单一只读 Bearer Token**（见 `API_CONTRACT.md` §4.9） |
| 授权 / RBAC | **不引入**（超出赛题范围，违背最小依赖） |
| 网络边界 | B 的 API 仅在受信网络内暴露；不直接暴露数据库端口 |
| 对外暴露 | **禁止** C 直连数据库；禁止 API 返回数据库内部字段 |
| 凭据管理 | 一律环境变量注入；仓库只留 `.env.example`；`.gitignore` 已排除 `.env*`、`*.pem`、`*.key` |
| 演示环境 | 若开启 token，演示脚本从环境变量读取，**不写入仓库或录屏** |

> **声明义务**：赛题要求"参赛者应在 README 中**声明实际使用的接口与权限**"。该声明见 `README.md`「ZSvirt 集成声明」章节。

## 6. 红线（违反即视为缺陷）

1. **禁止**把未脱敏的凭据写入数据库、日志、API 响应或 `Event.raw`。
2. **禁止**把真实 token / 密码 / 密钥 / 证书提交到仓库（`.gitignore` 已覆盖，但提交前仍需人工复核）。
3. **禁止**把局域网地址、个人机器路径写进产品源码或文档。
4. **禁止**在诊断证据（`Diagnosis.evidence`）中回显敏感字段原文。
5. **禁止**在演示录屏中出现真实凭据或内网拓扑细节。
